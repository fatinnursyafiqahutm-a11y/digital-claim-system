for the Digital Claim System is shown in **Figure 4.18**. It comprises 18 entities, each representing a distinct functional element of the system. These entities have been carefully designed based on the system requirements and intended operations to support claim submissions, approval workflows, notifications, and reporting functionalities. The relationships between entities are modeled using one-to-many and many-to-one cardinalities, based on real-world interactions between system components. Foreign keys are implemented to maintain referential integrity across tables. This ERD acts as a blueprint for database implementation in the Digital Claim System and ensures that the backend structure aligns with the system's functional modules, providing a scalable and maintainable foundation for future enhancements.

### 4.4.1 Table Description

**Table 4.4: Description Table**

| No | Table | Description |
|----|-------|-------------|
| 1 | Users | Stores employee credentials including email and password. Each user has a unique userID. |
| 2 | Claims | Main table that tracks claim entries including amount, submission date, and status. |
| 3 | Receipts | Stores receipt data submitted by users, including receipt date, amount, and file path. |
| 4 | Claim_Submissions | Captures the link between claim and receipt upon submission, including date and claimed amount. |
| 5 | Claim_Approval | Tracks approval or rejection actions by finance/admin with associated remarks and timestamps. |
| 6 | Claim_Status | Maintains historical log of claim statuses (e.g., pending, approved, rejected) for audit trail. |
| 7 | Email_Notification | Stores automated notifications generated by the system, including email body, title, and date. |
| 8 | Claim_Report | Stores summarized data for reports including user reference, claim ID, and approved amount. |
| 9 | AccommodationClaim_Form | Captures details for accommodation-related claims such as dates, name, country, and amount. |
| 10 | TransportationTripClaim_Form | Handles claims for travel including origin, destination, and transport details. |
| 11 | PetrolClaim_Form | Stores petrol-related claim data including date and amount. |
| 12 | TollClaim_Form | Contains information for toll claims including date and amount. |
| 13 | EntertainmentClaim_Form | Includes details such as customer and company name for entertainment expense claims. |
| 14 | MedicalClaim_Form | Stores data related to medical reimbursements including date and amount. |
| 15 | PhoneBillsClaim_Form | Handles phone bill claims with receipt references and total amount claimed. |
| 16 | OfficeParkingClaim_Form | Contains data for parking claims made at office premises. |
| 17 | ClientParkingClaim_Form | Captures details for claims related to client site parking expenses. |
| 18 | OtherClaims_Form | Serves as a general-purpose table for claims that do not fall under specific predefined categories. |

**Database Business Rules:**
- Each user has a unique userID as primary key
- Claims table references Users table through foreign key relationship
- One user can submit multiple claims (one-to-many relationship)
- Each claim can have multiple receipts attached
- Claim_Submissions links claims to receipts (many-to-many relationship)
- Each claim has one approval record in Claim_Approval table
- Claim_Status maintains audit trail with timestamps for status changes
- Email_Notification records all system-generated notifications
- Claim type-specific tables (AccommodationClaim_Form, PetrolClaim_Form, etc.) store additional details based on claim category
- Foreign keys ensure referential integrity across all related tables
- Claim_Report aggregates data from multiple tables for reporting purposes

## Summary of Interface Design Principles

The interface design for the Digital Claim System follows these core principles:

1. **Consistency**: All pages maintain consistent navigation, layout, and design patterns
2. **Clarity**: Clear labeling, intuitive organization, and logical flow
3. **Accessibility**: Easy-to-use interface for users with varying technical expertise
4. **Responsiveness**: All interfaces designed to work on desktop, tablet, and mobile devices
5. **Role-Based Display**: Different views and options for Employee vs. Admin roles
6. **Validation Feedback**: Clear error messages and success confirmations
7. **Efficiency**: Minimal clicks required to complete common tasks
8. **Transparency**: Clear status indicators and process visibility
9. **Security**: Password fields masked, sensitive actions require confirmation
10. **Flexibility**: Dynamic forms that adapt to claim type selected

All interface mockups were created using Canva during the design phase to validate layout and user flow before development implementation.
